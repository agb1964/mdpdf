## Подтверждённые находки и их состояние

### R-01. Коллизия временного PDF при `--overwrite` — исправлено

Раньше `temporary_path` различал только PID. Два потока одного процесса,
пишущие один путь с `--overwrite`, использовали один временный файл. В исходной
проверке один из двух писателей стабильно завершался ошибкой.

В текущем рабочем дереве к PID добавлен процессный атомарный счётчик, а тест
`output::tests::concurrent_overwriting_writers_both_succeed` проверяет, что оба
писателя завершаются успешно, итоговый PDF цел и временных файлов не остаётся.

Проверено 2026-08-05:

```text
cargo test --locked output::tests --lib
13 passed; 0 failed
```

### R-02. Молчаливое затирание `--emit-*` — исправлено

Раньше `--emit-ast` и `--emit-typst` использовали `fs::write`, игнорировали
`--overwrite` и молча заменяли существующий файл.

В текущем рабочем дереве без `--overwrite` применяется `File::create_new`, а
коллизия возвращает `AppError::OutputExists` с кодом 8. Пользовательский риск
молчаливой потери существующего файла устранён.

Regression-тесты проверяют обе стороны контракта: существующий AST без
`--overwrite` остаётся неизменным, а существующий Typst-файл с `--overwrite`
заменяется.

Исходная формулировка смешивала этот дефект с отсутствием атомарной записи.
Последнее не устранено: при `--overwrite` файл открывается напрямую и при ошибке
может остаться частичным. ТЗ требует атомарность для PDF, но не обещает её для
диагностических `--emit-*`, поэтому это отдельный необязательный hardening, а не
часть открытого дефекта R-02.

### R-03. Внешние ссылки SVG внутри `url(...)` — исправлено

Раньше `external_reference` проверял только `href`/`xlink:href` и пропускал
`style="fill:url(http://...)"` и `<style>@import url("https://...")</style>`.

Текущий код проверяет `url(...)`, отвергает запрещённые схемы и сохраняет
локальные ссылки `url(#gradient)`. Значение `href=http://...` без кавычек не
поддерживается намеренно: это невалидный XML, который отклоняет SVG-парсер.

Проверено 2026-08-05:

```text
cargo test --locked svg::tests --lib
11 passed; 0 failed
```

### R-04. Синхронизация каталога после `rename` — hardening, не дефект ТЗ

ТЗ §12.2 требует `flush`, `sync_all`, если он поддерживается реализацией, и
безопасное переименование с сохранением старого PDF при ошибке. Оно не обещает
полную crash-consistency записи имени файла после потери питания.

Поэтому отсутствие `fsync` каталога в исходном коде не было нарушением ТЗ.
Текущий рабочий diff добавляет `sync_all` каталога в режиме best effort; ошибка
игнорируется ради переносимости. Это усиливает Unix-путь, но не является
подтверждаемой гарантией на каждой платформе.

## Открытые риски

### R-05. Lowercase-копия SVG меняет диагностику

`external_reference` приводит весь SVG к нижнему регистру. Это создаёт полную
дополнительную копию ресурса и возвращает пользователю изменённое значение
ссылки: например, регистр base64 или path уже не совпадает с исходным SVG.
Фильтрация остаётся безопасной, но диагностика неточна. При исправлении нужно
искать схемы без учёта регистра, а найденный фрагмент возвращать из исходного
текста.

### R-06. TOCTOU в классификации ошибки `replace()`

После неудачного `rename` код использует `target.exists()`, чтобы решить,
запускать ли backup-ветку. Проверка может устареть при параллельном изменении
цели. Это не ломает защиту `overwrite=false`, но в редкой гонке способно дать
неверную диагностику или выбрать не ту ветку восстановления.

### R-07. Совпадающие пользовательские пути

Конфигурация явно не запрещает совпадение input, `--emit-ast`, `--emit-typst`
и PDF output. Без `--overwrite` новое резервирование закрывает часть опасных
случаев. С `--overwrite` пользователь явно разрешает замену, поэтому объявлять
любое совпадение дефектом без решения в ТЗ нельзя. Нужен отдельный контракт:
запрет алиасов либо документированная семантика порядка записей.

### R-08. Symlink-TOCTOU ресурсов — принятый риск v1

Между `canonicalize` и `File::open` в `compiler/files.rs` остаётся окно замены
символической ссылки. Оно уже задокументировано и осознанно принято для v1.
Этот аудит не предлагает менять модель доступа к ресурсам без отдельного
security-требования.

## Наблюдения, которые не являются дефектами

- `File::create_new` и последующий cleanup пустой резервации — оправданная цена
  атомарной защиты имени PDF.
- Windows backup-and-restore сложнее Unix `rename`, но нужен для сохранения
  старого файла при неудачной замене.
- `Box<CompileError>` уменьшает размер часто передаваемого `AppError`; это
  локальный компромисс представления.
- Пары вариантов ошибок `X`/`XAt` упрощают форматирование через `thiserror`,
  хотя требуют обновлять `exit_status()` при добавлении вариантов.
- Двойная защита размера через `metadata()` и ограниченное чтение оправданна:
  первая быстро отвергает большой файл, вторая обязательна для stdin.
- `normalize_line_endings` может временно расходовать больше размера входа из-за
  двух `replace`; ТЗ §16.2 не устанавливает для этого отдельного лимита памяти.
- `ExitStatus::GeneralError` сейчас не порождается production-кодом, но коды
  завершения входят в публичный контракт и по ТЗ §26 не меняются ради чистоты.
- `AppConfig` с публичными полями неудобен для тестовых литералов, но это
  сопровождаемость, не пользовательская ошибка.

## Идеи улучшения тестируемости

Эти пункты не требуют изменений сами по себе:

- передавать stdout/stderr в `app::run`, если e2e-проверок вывода станет
  недостаточно;
- отделить вычисление отсутствующих глифов от печати предупреждения;
- проверять Windows replacement на Windows CI;
- добавить fault-injection для `ENOSPC`/ошибки `sync_all`, если этот класс сбоев
  станет практически значимым;
- рассмотреть атомарную запись `--emit-*`, если она станет частью публичного
  контракта.
