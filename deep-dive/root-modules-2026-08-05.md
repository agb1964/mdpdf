# Deep Dive: корневые модули `src/*.rs`

Дата: 2026-08-05 · Режим: compact · Уровень: mid

## Overview

Корень `src/` — это **оболочка приложения**, а не предметная логика. Вся конвертация живёт в модулях-слоях (`markdown` → `ast` → `typst_gen` → `compiler`), а корневые файлы отвечают за границы процесса: аргументы, конфигурацию, ввод, вывод, коды завершения и одну общую политику безопасности (SVG).

Разделение проходит по линии «что снаружи процесса»:

| Файл | Ответственность |
|------|-----------------|
| `cli.rs` | описание поверхности CLI (clap-структура), больше ничего |
| `config.rs` | CLI → типизированная конфигурация + проверки, недоступные clap |
| `source.rs` | чтение и нормализация входа, лимит размера |
| `app.rs` | оркестрация конвейера, порядок шагов |
| `output.rs` | атомарная запись PDF |
| `svg.rs` | проверка SVG на внешние ссылки (лист-модуль без зависимостей) |
| `error.rs` | корневой `AppError` + стабильные коды завершения |
| `lib.rs` | объявление слоёв + `run_cli()`: разбор аргументов и маппинг ошибки в `ExitCode` |
| `main.rs` | 5 строк: вызов `run_cli()` |

## Key Components

### `app.rs` — конвейер
- `run(args)` — единственная точка, где виден порядок шагов: чтение → парсинг → валидация → генерация Typst → компиляция → запись.
- `warn_about_missing_glyphs()` — предупреждает о символах без глифа; PDF всё равно создаётся.
- `parse()` / `markdown_error()` — оборачивают ошибку парсера в `AppError` с позицией `файл:строка:столбец`.
- `write_ast()` / `write_text()` — диагностические выводы `--emit-ast` / `--emit-typst`.

### `config.rs` — нормализация намерения
- `AppConfig::from_cli()` — решает, будет ли вообще выходной PDF (`--check`, «только `--emit-*`», stdin без `-o`).
- `render_options()` — парсит `margin`/`font-size` в типизированные `Length` и валидирует.
- `base_dir()` — база для разрешения путей к картинкам; для stdin — `.`.
- `From<PaperArg> for PaperSize` — перевод CLI-enum в доменный.

### `source.rs` — вход
- `read_source()` → `read_file()` / `read_stdin()`.
- `read_limited()` — читает поток с `take(LIMIT + 1)`.
- `decode_and_normalize()` — BOM, UTF-8, NUL, CRLF/CR → LF.

### `output.rs` — выход
- `write_pdf_atomically()` — резервирование имени, временный файл, `sync_all`, переименование.
- `replace()` — переименование поверх существующего файла с откатом на Windows-пути.
- `temporary_path()` / `backup_path()` — служебные имена рядом с целью, с PID в имени.

### `svg.rs` — политика ресурсов
- `looks_like_svg()` — эвристика по первым 1024 байтам.
- `external_reference()` — построчный поиск `href`/`xlink:href` с запрещёнными схемами.

### Остальные (кратко)
- `cli.rs` — только декларация флагов + тесты на значения по умолчанию; никакой логики.
- `error.rs` — `AppError` (thiserror) и `ExitStatus` с фиксированными кодами 0–9; `exit_status()` — единственное место маппинга.
- `lib.rs` — `#![forbid(unsafe_code)]`, список слоёв в docs, `run_cli()` с цепочкой `caused by` под `--verbose`.
- `main.rs` — `ExitCode` из `run_cli()`.

## Концепции и решения

### 1. Ранняя проверка размера до чтения (`source.rs`)
**Что:** размер файла берётся из `fs::metadata()`, а не после `read_to_end()`. Для stdin, где размера нет, читается `LIMIT + 1` байт.
**Зачем:** отказ по 32 MiB не должен стоить 32 MiB памяти. `+1` — минимальный способ отличить «ровно по лимиту» от «слишком много», не буферизуя лишнего. Тест с разреженным файлом (`set_len`) проверяет именно это: файл на диске почти пустой, но по метаданным превышает лимит.
**Альтернатива:** проверка после чтения — проще, но открывает тривиальный DoS на память.

### 2. Атомарная запись через переименование (`output.rs`)
**Что:** PDF формируется целиком в памяти → временный файл в **том же каталоге** → `flush` + `sync_all` → `rename`.
**Зачем:** `rename` в пределах одной ФС атомарен — читатель видит либо старый файл, либо новый, но не полузаписанный. `sync_all` перед переименованием: без него после отключения питания можно получить «успешно созданный» пустой PDF (имя есть, данных ещё нет).
**Когда так делать:** всегда, когда результат — один файл и частичная запись хуже отсутствия записи.

### 3. Резервирование имени через `File::create_new` вместо `exists()`
**Что:** без `--overwrite` имя занимается атомарной операцией «создай, если нет».
**Зачем:** классический TOCTOU: между `exists()` и записью два параллельных запуска оба считают файл отсутствующим, и второй молча затирает первый. Тест `only_one_of_two_concurrent_writers_succeeds` фиксирует это поведение на двух потоках.
**Цена:** резервация — свой пустой файл, и при любой последующей ошибке его обязательно надо снять (замыкание `cleanup`), иначе на диске остаётся пустышка.

### 4. Windows-путь в `replace()`: backup вместо удаления
**Что:** если `rename` поверх цели не сработал, старый файл **переименовывается** в `.backup`, а не удаляется; при провале второго шага он возвращается на место.
**Зачем:** на Unix ветка не нужна, но на Windows `rename` поверх существующего файла — ошибка. Удалить цель заранее означало бы: сбой второго шага = потеря и старого, и нового результата. Backup даёт откат.

### 5. Ошибка с позицией — отдельный вариант enum, а не поле
**Что:** пары `Markdown` / `MarkdownAt`, `Compile` / `CompileAt`.
**Зачем:** позиция известна не всегда, а оборачивание в момент, когда доступен текст документа (`app.rs`), позволяет вычислить `line:column` из `SourceSpan` один раз и не тащить исходник в доменные модули. Доменный слой возвращает span, приложение превращает его в `input.md:12:5`.
**Альтернатива:** `Option<Location>` внутри одного варианта — меньше вариантов, но `#[error("{location}: {source}")]` тогда не выразить декларативно.

### 6. Коды завершения как enum, а не числа
**Что:** `ExitStatus` с `code()` и `AppError::exit_status()` — единственная точка маппинга.
**Зачем:** коды — часть публичного контракта CLI (скрипты на них полагаются). Enum + тест `exit_codes_match_specification` не дают им «съехать» при рефакторинге. Отдельный код 9 для нарушения политики ресурсов достаётся не новым вариантом `AppError`, а разбором вложенного `CompileError` — политика живёт в компиляторе, дублировать её на уровне приложения не нужно.

### 7. `Box<CompileError>` в одном варианте
**Что:** только `Compile` и `CompileAt` боксируют источник.
**Зачем:** размер enum равен размеру самого крупного варианта, а `AppError` возвращается из каждой функции конвейера. Один крупный вариант удорожает все `Result` в программе.

### 8. Предупреждения не прерывают конвейер
**Что:** отсутствующие глифы, деградировавшие mermaid-диаграммы, диагностика Typst — всё в stderr, PDF создаётся.
**Зачем:** решение «приемлема ли потеря» принимает человек. Отсутствующий глиф не рисуется квадратиком — он просто исчезает, и без предупреждения о потере узнают, только сверив PDF с исходником.

### 9. Проверка SVG без XML-парсера
**Что:** `external_reference()` ищет `href`/`xlink:href` посимвольно, поддерживая пробелы вокруг `=` и обе кавычки. `data:` запрещена наравне с сетевыми схемами.
**Зачем:** полноценный XML-парсер здесь избыточен и сам был бы поверхностью атаки. `data:` в списке потому, что это тоже способ протащить произвольный, неучтённый лимитами блок байт.
**Компромисс:** текст приводится к нижнему регистру целиком, поэтому в сообщении об ошибке значение возвращается в lower-case (видно в тесте с base64: `aaaa`). Для диагностики приемлемо, для точного воспроизведения значения — нет.
**Защита в глубину:** модуль вызывается дважды — в `mermaid` (нефатально, диаграмма деградирует в блок кода) и в `compiler` (фатально, для всех ресурсов).

### 10. Двухступенчатый выход из конвейера (`app.rs:84`)
**Что:** режим «только `--emit-*`» завершается **до** компиляции, а `--check` проходит весь конвейер и лишь не пишет PDF.
**Зачем:** `--check` обязан ловить ошибки компиляции — иначе он не проверка. `--emit-typst` без `-o` — про инспекцию промежуточного представления, компиляция там лишняя работа. Отсюда неочевидное условие `!config.check && config.output.is_none()`, а `None` в `config.output` ниже по коду однозначно означает `--check`.
