## Milestone 2 — AST → Typst

Сделано:

- Четыре раздельные функции экранирования (§23): `string_literal`, `text_content`,
  `url_literal`, `path_literal`.
- `TypstGenerator`, `GeneratedTypst`, `ResourceReference`; типизированные
  `PaperSize` и `Length` с проверками §20.2 (поле ≤ половины меньшей стороны,

- Все узлы AST переводятся в вызовы функций шаблона; ручной строковой разметки нет.
- Изображения получают виртуальные пути `/mdpdf-resources/000001.png`,
  реальные пути в Typst-исходник не попадают (§24.6).
- Встроенный шаблон переписан: страница, поля, шрифты, интервалы, заголовки,
  цитаты, код, таблицы, номера страниц, оглавление, нумерация заголовков (§21).
- Вывод детерминирован и отформатирован по §26; `--emit-typst` работает.

Не закрыто:

- `text_content` генератором не используется: пользовательский текст всюду
  передаётся строковыми литералами как более безопасная форма. Функция
  публичная и покрыта тестами, потому что §23 требует её наличия.

## Milestone 3 — Typst → PDF

Сделано:

- `MdpdfWorld`: ограниченное окружение Typst (§32). Отдаёт только `/main.typ`,
  встроенные шрифты и заранее зарегистрированные изображения. Нет доступа
  к файловой системе, окружению, сети, пакетам, системным шрифтам; `today`
  всегда `none`, поэтому вывод не зависит от времени.
- Встроенные шрифты разбираются один раз на процесс через `OnceLock`,
  порядок регистрации фиксирован, покрытие кириллицы проверяется тестом (§34).
- Разрешение изображений (§33): путь канонизируется, принадлежность каталогу
  документа проверяется после раскрытия `..` и симлинков, абсолютные пути
  запрещены, формат определяется по содержимому (PNG/JPEG/GIF/SVG), действуют
  лимиты §40.
- Диагностики Typst переводятся в собственную модель (§37): наружу уходит
  только текст, позиция в сгенерированном Typst и подсказки — без `FileId`,
  Rust-типов и debug dump.
- `EmbeddedTypstCompiler` + трейт `PdfCompiler` по §31; проверка сигнатуры
  `%PDF-` и минимального размера (§39).
- Предупреждения Typst не теряются: печатаются в stderr, PDF всё равно
  создаётся (§38).
- `--check` проходит весь конвейер до компиляции и возвращает 0, не записывая PDF.

Найдено и исправлено при первом же прогоне компилятора:

- изображение выводилось блочной `figure` внутри `par()` — Typst выдавал
  предупреждение «block may not occur inside of a paragraph and was ignored»,
  картинка молча пропадала. Теперь `box(image(...))`, alt уходит строкой
  в PDF как описание, а не как подпись;
- нарушение политики доступа к ресурсу возвращало код 7 вместо 9 (§43);
- диагностики Typst не показывались: пользователь видел только
  «PDF compilation failed» без причины.

## Принятые решения

| Решение | Причина |
|---|---|
| Имя крейта `mdpdf`, каталог остаётся `md2pdf` | Совпадение с командами и примерами ТЗ |
| `typst`/`typst-pdf` подключены уже на Milestone 0 | ТЗ §60 требует закреплённых версий в каркасе |
| `Vec<Spanned<Block>>` вместо `Vec<Block>` | §11 требует диапазоны и разрешает обёртку; структуры узлов §10 остались дословными |
| Проверка границ span — в парсере, не в `validate_document` | Сигнатура валидатора закреплена ТЗ и не принимает исходный текст |
| Добавлен `src/lib.rs`, которого нет в §7 | §42 требует `mdpdf::run_cli()`, то есть библиотечный таргет |
| YAML front matter молча отбрасывается | Решение пользователя; §9 оставлял вопрос открытым, §10.2 запрещает извлекать значения |
| Ошибки печатаются без префикса `mdpdf:` | Формат сообщения задан §16 дословно |
| Шрифты в обычном Git, без LFS | 3 МБ неизменяемых файлов; LFS ломает сборку при checkout без `lfs: true` |
| Лицензия MIT OR Apache-2.0 | Стандарт экосистемы Rust; ТЗ конкретную не задаёт |
| 7 advisories из дерева typst внесены в `ignore` | Безопасных версий нет, а typst закреплён `=0.15.1` (§36) |
| `--emit-ast`/`--emit-typst` без `--output` завершают конвейер успехом | §5.5 прямо говорит это про `--emit-typst`; на `--emit-ast` правило распространено по аналогии |
| Добавлена зависимость `typst-layout` | `PagedDocument` живёт в ней и из `typst` наружу не реэкспортируется |
| Изображение — inline `box`, а не блочная `figure` | В Markdown изображение внутри абзаца; блок внутри `par()` Typst игнорирует |
| Шаблон встраивается в `/main.typ`, отдельного `/template.typ` нет | §21 требует `include_str!`, §32 делает отдельный виртуальный файл необязательным |

Открытая неоднозначность ТЗ: §42 приводит конвейер, в котором `--emit-*` не
прерывают работу и PDF всё равно пишется по пути по умолчанию, а §5.5 говорит
обратное. Выбран вариант §5.5. Если нужен вариант §42 — менять `AppConfig::from_cli`
(поле `emit_only`) и ранний выход в `app::run`; поведение закреплено тестом
`emit_ast_writes_valid_json_and_succeeds`.

## Долги и открытые вопросы

- Гейт покрытия в CI считает общий процент, а не помодульный: `cargo-llvm-cov`
  помодульного порога не умеет. Требование §17 и §29 — по модулям, поэтому
  цифры `markdown`, `ast` и `typst_gen` нужно смотреть глазами в выводе job.
- `ignore` в `deny.toml` — временное подавление; пересматривать при каждом
  подъёме версии typst.
- Дубликат `syn` в дереве зависимостей оставлен видимым намеренно: исчезнет
  при обновлении `clap`/`thiserror`.
- `opt-level = "z"` и `panic = "abort"` не включены — по §56/§57 решение
  принимается по benchmark, которого ещё не было.
- Репозиторий без remote: workflow не запускались ни разу.
