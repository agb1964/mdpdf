# Журнал работ

Состояние проекта относительно **ТЗ редакции 2.0**
(`docs/mdpdf-technical-spec-v2.md`), принятые решения и оставшиеся работы.
Обновляется при закрытии значимых задач и перед выпуском.

Последнее обновление: 2026-07-26.

Старое ТЗ (`docs/Техническое задание.pdf`) заменено редакцией 2.0. Журнал
переписан под новую модель готовности: не milestones 0–5 как план работ, а
готовность продукта к публичному выпуску **версии 1.0** (ТЗ §24, §29).

| Область | Статус |
|---|---|

| Публичный выпуск 1.0 | не объявлен |

Проверка локально: `make ci` (fmt, check, clippy, test, doc, deny).

На 2026-07-26 — **296 тестов**, все проходят. Release-бинарник ≈ **34 МБ**:
Typst и пять шрифтов реально встроены. Команда
`mdpdf document.md -o document.pdf` создаёт корректный PDF на машине без
Typst, Chromium, Pandoc и LaTeX.

По ТЗ §3 и §21.1 подтверждённая платформа пока только **macOS ARM64**.
Windows и Linux считаются реализованными в коде, но **не подтверждёнными**,
пока CI не пройдёт на remote.

## Что уже реализовано

Кратко по слоям (ТЗ §3, §5). Подробности по этапам разработки — ниже.

1. Каркас, CLI, ошибки, коды 0–9, CI/release YAML, шрифты, шаблон.
2. Markdown → собственный AST (`pulldown-cmark` не экспортируется).
3. AST → безопасный Typst source (экранирование, виртуальные пути).
4. Встроенный компилятор + `MdpdfWorld` (без FS/сети/пакетов/системных шрифтов).
5. Атомарная запись PDF, защита от перезаписи, stdin, `--check`, `--emit-*`.
6. Лимиты ресурсов, fuzz targets, golden AST/Typst/структура PDF.
7. Исправления по внешнему review (паника UTF-8, nesting, коды выхода, гонки).

### Замеры (ТЗ §16.1), release, Apple Silicon

| Сценарий | Результат |
|---|---:|
| Запуск без документа | ~0 мс |
| Markdown 1 MiB, полный конвейер | ~0,21 с |
| Пик RSS, 1 MiB | ~250–350 МБ |
| Markdown 10 MiB (~3690 стр.) | ~2,3 ГБ |
| Размер release-бинарника | ~34 МБ |

Обязательный лимит памяти на 10 MiB MD **не устанавливается** (ТЗ §16.2):
пик даёт batch-layout Typst (`PagedDocument`), а не AST/генератор `mdpdf`.

## История реализации (как строилось)

Ниже — журнал закрытых этапов. Нумерация milestones — историческая; план
работ ТЗ 2.0 на milestones не опирается.

### Milestone 0 — каркас

- Крейт `mdpdf` (каталог `md2pdf`); `typst`/`typst-pdf` `=0.15.1`,
  `pulldown-cmark` `=0.13.4`, `Cargo.lock` в Git.
- Модули по архитектуре трёх этапов; `#![forbid(unsafe_code)]`; `AppError` +
  коды завершения.
- CLI: путь выхода, `--check`, `--emit-*`, `--output` обязателен при stdin.
- Нормализация входа: BOM, CRLF/CR → LF, нулевой байт — ошибка, лимит 32 MiB.
- Noto Sans (5 начертаний) + OFL; `assets/template.typ`.
- CI/release workflows (YAML), `deny.toml`, `Makefile`, toolchain, README,
  AGENTS.md, лицензии.

### Milestone 1 — Markdown → AST

- Собственный AST: блоки, inline, таблицы, списки (start, task-items), spans.
- `AstBuilder` — стековый автомат; HTML/math/footnotes → unsupported;
  несовместимое закрытие / незакрытый контейнер — ошибки.
- Типы `pulldown-cmark` наружу не выходят; `validate_document`; диагностика
  `file:line:col`.
- Golden AST (4 фикстуры), детерминизм, proptest на отсутствие паник.

### Milestone 2 — AST → Typst

- Контекстное экранирование; `TypstGenerator` + `ResourceReference`.
- Типизированные `PaperSize` / `Length` с проверками полей и размера шрифта.
- Узлы → вызовы функций шаблона; изображения → `/mdpdf-resources/NNNNNN.ext`.
- Шаблон: страница, шрифты, заголовки, цитаты, код, таблицы, TOC, нумерация.
- Детерминированный вывод; `--emit-typst`.

### Milestone 3 — Typst → PDF

- `MdpdfWorld`: только main source, шрифты, заранее разрешённые изображения;
  `today` = none.
- Шрифты: `OnceLock`, фиксированный порядок, кириллица в тестах.
- Изображения: канонизация, каталог документа, symlink, magic bytes, лимиты;
  SVG с http/https/file/data — отказ.
- Диагностики Typst → пользовательский формат без `FileId`/debug dump.
- `EmbeddedTypstCompiler` + `PdfCompiler`; `%PDF-` и минимальный размер.
- Предупреждения Typst → stderr, PDF всё равно пишется; `--check` без записи.

Исправления при первом прогоне компилятора:

- изображение: `box(image(...))` вместо `figure` внутри `par()`;
- код доступа к ресурсу → 9, не 7;
- диагностики Typst стали видны пользователю.

### Milestone 4 — интеграция CLI

- Атомарная запись: temp в каталоге цели → flush/sync → rename; cleanup при ошибке.
- Без `--overwrite` — код 8, старый файл цел.
- `Created` / `Checked`, `--quiet`; AST validation → код 5 + позиция.
- E2E happy path (14 сценариев).
- Windows: backup-and-restore при замене; Unix — атомарный rename.
- Резервация имени через `File::create_new` (без TOCTOU `exists()`).

### Milestone 5 — hardening

- Лимиты глубины/узлов/входа применяются; вход не читается сверх 32 MiB.
- Fuzz: `fuzz_markdown_parser`, `fuzz_typst_escape`, `fuzz_ast_validation`
  (корпус ~4619 / 454 / 4651; 60 с — без падений). `fuzz_typst_escape` —
  инвариант «нельзя вырваться из строкового литерала».
- `builder` — `pub(crate)`; spans обходят таблицы и вложенные ссылки/изображения.
- Ресурс: один open; symlink-за-каталог; `path_literal` только `/mdpdf-resources/`.
- Golden PDF (структура): страницы, размеры, шрифты, число изображений.
  Нашёл дефект mono-шрифта в `raw` (show-правило Typst).

### Исправления по внешнему review

Отчёты: `docs/code-review-2026-07-26.md`, `docs/code-analysis-2026-07-26.md`.

| Дефект | Суть |
|---|---|
| Паника на не-ASCII в URI | срез UTF-8 не по границе символа |
| Переполнение стека | `MAX_NESTING_DEPTH` не применялся |
| Код 5 недостижим | AST validation шла как Markdown (4) без позиции |
| Лимит входа после чтения | файл читался целиком, потом сравнивался |
| Потеря старого PDF | целевой файл удалялся до успешной замены |
| Гонка overwrite | `exists()` + запись вместо `create_new` |
| `//host/x.png` | protocol-relative не считался сетевым |
| `make golden-update` | обновлял только AST, не Typst |

Общее: дефекты жили в редких ветках (многобайтовый ввод, экстремальная
вложенность, сбой rename, параллельные запуски). Высокое покрытие их не
поймало — это одна из причин, почему ТЗ 2.0 сняло жёсткий порог 90 % (§19.3).

## Принятые решения

| Решение | Причина |
|---|---|
| Имя крейта `mdpdf`, каталог `md2pdf` | совпадение с командами и примерами |
| `typst`/`typst-pdf` с Milestone 0 | закреплённые версии в каркасе |
| `Vec<Spanned<Block>>` | spans нужны для диагностик; семантика узлов сохранена |
| Проверка границ span в парсере | валидатору исходный текст не передаётся |
| `src/lib.rs` + `mdpdf::run_cli()` | библиотечный entry для CLI/тестов |
| YAML front matter молча отбрасывается | ТЗ §8: извлечение в 1.0 не требуется |
| Ошибки без префикса `mdpdf:` | формат диагностики из ТЗ |
| Шрифты в Git, без LFS | ~3 МБ; LFS ломает checkout без `lfs: true` |
| MIT OR Apache-2.0 | стандарт Rust-экосистемы |
| Advisories typst в `deny` ignore | нет безопасных версий при pin `=0.15.1` (ТЗ §22) |
| `--emit-*` без `--output` → успех, без PDF | ТЗ §7.5 (обязательное поведение) |
| Зависимость `typst-layout` | `PagedDocument` не реэкспортируется из `typst` |
| Изображение — inline `box`, не `figure` | Markdown-картинка внутри абзаца; блок в `par()` игнорируется |
| Шаблон в `/main.typ`, отдельного `/template.typ` нет | `include_str!` + один виртуальный main |
| Лимиты структуры в `ast` / parser | parser не должен зависеть от `compiler` |
| Невалидные `--margin`/`--font-size` → код 6 | проверки оформления в `RenderOptions` |
| `MAX_URL_BYTES` живёт в `typst_gen` | нет обратной зависимости `compiler` ← `typst_gen` |
| Память 10 MiB MD ~ 2,3 ГБ — не дефект | ТЗ §16.2: пик Typst; лимит не обязателен |
| Release profile: thin LTO, CGU=1, strip | ТЗ §17.3: достаточно; `opt-level=z` / `abort` не требуются |
| Нет perceptual comparison в 1.0 | ТЗ §20: опционально; структурных golden PDF хватает |
| Coverage — информационный, без hard gate 90 % | ТЗ §19.3 |
| Дубль `syn` v2/v3 — оставить видимым | ТЗ §22: не runtime-ошибка; hide через skip теряет сигнал |

## Оставшиеся работы (ТЗ §25)

### Обязательно перед 1.0 (§25.1)

#### 1. Публикация репозитория и первый прогон CI

**Единственная обязательная незавершённая задача.**

У репозитория нет remote. Workflow `ci.yml` / `release.yml` ни разу не
запускались на GitHub. «Зелёный CI» = только локальный `make ci` на macOS ARM64.

Нужно фактически проверить (ТЗ §21.3):

1. создать remote;
2. запустить CI;
3. все основные jobs;
4. починить ошибки workflow;
5. сборку Windows и Linux (в т.ч. Windows-ветку атомарной замены §12);
6. clean-environment job (без Typst);
7. публикацию release-артефактов;
8. что бинарник работает без установленного Typst.

**Риск:** высокий. Пока remote нет, нельзя утверждать официальную поддержку
Windows/Linux (ТЗ §21.1–21.3).

**Оценка:** час на выкладку и первый прогон + время на починку того, что вскроется.

### По результатам CI (§25.2)

Только реальные ошибки первого прогона: платформа, пакеты сборки, пути, shell,
release packaging, файловые операции.

### Необязательно (§25.3)

Только при практической потребности:

| Работа | Когда имеет смысл |
|---|---|
| Perceptual PDF comparison | регулярные визуальные регрессии, которые не ловят структурные тесты |
| Подбор release profile | profiler / заметное ухудшение размера или скорости |
| Помодульный coverage gate | если review перестаёт ловить просадку критических модулей |
| Оптимизация размера / памяти | обычный документ тормозит или не хватает RAM (ТЗ §17.2) |
| Linux ARM64 / macOS x86-64 artifacts | если workflow собирает без лишних затрат |
| Обновление Typst | отдельная задача + full suite + golden PDF |
| Syntax highlighting, новые шрифты | явный пользовательский сценарий (ТЗ §27) |

### Что не является долгом

Пункты, которые раньше выглядели как «незакрытая работа» или баг; в ТЗ 2.0
сняты или явно не требуются:

- **Память на 10 MiB MD.** Не дефект `mdpdf`; лимит не обязателен (§16.2).
- **Perceptual comparison.** Не условие 1.0 (§20).
- **Coverage 90 %.** Порог отменён (§19.3).
- **`opt-level = "z"` / `panic = "abort"`.** Не требуются (§17.3, §23).
- **Дубль `syn`.** Не ошибка (§22).
- **`text_content` и неиспользуемые варианты ошибок.** Внутреннее API можно
  упрощать (§4.2, §10.2); не нужно сохранять мёртвое ради старого ТЗ — и не
  нужно «доделывать» ради полноты, если поведение уже покрыто.
- **Syntax highlighting в code blocks.** Не в scope 1.0; язык — подпись.

## Что не переделывать без дефекта (ТЗ §26)

- собственный AST и стековый parser;
- виртуальные пути изображений;
- ограниченный Typst World и модель шрифтов;
- inline-изображение через `box(image(...))`;
- атомарное резервирование output и Windows backup-and-restore;
- коды завершения и поведение `--emit-*`;
- текущий release profile и защитные лимиты.

Архитектурная «красота» сама по себе — не повод переписывать работающее.
