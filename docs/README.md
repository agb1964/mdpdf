# Документация `mdpdf`

Эта страница объясняет назначение документов и порядок их актуализации.

## Источники истины

| Документ | Статус | Назначение |
|---|---|---|
| [`mdpdf-technical-spec-v2.md`](mdpdf-technical-spec-v2.md) | нормативный | требования к поведению, архитектуре, безопасности и готовности версии 1.0 |
| [`../README.md`](../README.md) | пользовательский | установка, CLI, поддерживаемый Markdown и ограничения |
| [`progress.md`](progress.md) | живой | фактический статус, принятые решения и оставшиеся работы |
| [`../CONTRIBUTING.md`](../CONTRIBUTING.md) | живой | локальная разработка, проверки и порядок внесения изменений |
| [`releasing.md`](releasing.md) | живой | подготовка, публикация и проверка релиза |
| [`../SECURITY.md`](../SECURITY.md) | живой | модель угроз и сообщение об уязвимостях |
| [`../CHANGELOG.md`](../CHANGELOG.md) | живой | пользовательские изменения по версиям |
| [`../assets/fonts/README.md`](../assets/fonts/README.md) | живой | происхождение, контрольные суммы и обновление встроенных шрифтов |
| [`../AGENTS.md`](../AGENTS.md) | нормативный для разработки | краткие инварианты проекта для автоматизированных и ручных изменений |
| [`mermaid-mmdr-plan.md`](mermaid-mmdr-plan.md) | план (утверждённая политика) | решение Mermaid → mmdr → SVG → PDF: ADR-смысл, фазы A–G, риски, приёмка |

При противоречии желаемое поведение определяет ТЗ. Фактически реализованное
поведение проверяется по исходному коду и тестам. Обнаруженное расхождение
нужно устранить или явно зафиксировать в `progress.md`, а не замалчивать.

## Исторические материалы

Следующие файлы являются снимками состояния на конкретную дату и не описывают
текущую реализацию:

- [`Техническое задание.pdf`](Техническое%20задание.pdf) — первоначальная
  редакция ТЗ, заменённая редакцией 2.0;
- [`code-review-2026-07-26.md`](code-review-2026-07-26.md) — отчёт review до
  завершения Milestone 4 и 5;
- [`code-analysis-2026-07-26.md`](code-analysis-2026-07-26.md) — анализ
  дефектов, большая часть которых затем была исправлена.

Ссылки на старую нумерацию ТЗ в этих файлах сохранены как часть исторического
контекста. Findings из них нельзя считать открытыми без повторной проверки
текущего кода.

## Когда что обновлять

| Изменение | Обязательные документы |
|---|---|
| CLI или пользовательское поведение | `README.md`, ТЗ при изменении контракта, `CHANGELOG.md` |
| архитектура или границы слоёв | ТЗ, `AGENTS.md`, `progress.md` |
| план Mermaid/mmdr (статус фаз) | `mermaid-mmdr-plan.md`, `progress.md` |
| исправление значимого дефекта | `CHANGELOG.md`, при необходимости `progress.md` |
| зависимость Typst или parser | `Cargo.lock`, `deny.toml`, `CHANGELOG.md`, результаты golden PDF |
| встроенный шрифт | `assets/fonts/README.md`, лицензии, ТЗ, `README.md`, `CHANGELOG.md` |
| релиз | `CHANGELOG.md`, `progress.md`, при необходимости `README.md` |

Перед релизом документация проверяется по чек-листу
[`releasing.md`](releasing.md).
